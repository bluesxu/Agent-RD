### O-2 审查发现的分级没有判定标准，靠 agent 自由心证

**状态**：done　**影响**：rd-review（L2）　**完成于**：2026-08-10（skill-ce-uplift）

`blocking / important / nit` 三档方向是对的（离散不是连续），
但**每一档没有写死判定标准**，全靠 reviewer 自己拿捏。

**CE 踩过的坑**：它最初用 0.0~1.0 连续置信度 + 数值档位（0.50/0.60/0.65/0.75），
跑下来发现是伪精度——审查员全扎堆打 0.68~0.72，0.65 那条线附近全是抛硬币，
**模型根本没有能力区分 0.65 和 0.72**。改成离散档位后，
每一档绑一条**模型能诚实自查的行为条件**（不是形容词、不是「你有多确信」）。
踩坑记录：CE 的 `docs/solutions/skill-design/confidence-anchored-scoring.md`。

配套的一条：多个审查员都提到同一件事可以升一档，
**但前提是那几个审查员是真正独立派发的**（同一 context 里的多个视角不算多个证人）。

**怎么改**：给三档各写死行为判定条件；升档规则要绑独立性前提。

**完成方式**：
- 10 个行为条件名冻结进 `docs/authoring.md` §6.1（`contract-break` / `wrong-result-silent` /
  `fabricated-verification` / `guard-evasion` / `unhandled-failure-path` / `coverage-gap` /
  `contract-drift` / `redundant-logic` / `misleading-name` / `stale-doc`）。
- `rd-review/references/severity-rubric.md` 写每档的行为判据（模型能诚实自查的）。
- L2 报告每条 finding 必填 `- 判定条件: <名字>`，`check-artifacts` 枚举校验（缺/拼错点名），
  三节都写「无」的干净报告零 finding 照常通过。
- 升档独立性前提写进 rubric；**状态**：可证伪部分已机械化，独立性前提仍是指令（无机械门）。

**待办**

- [x] `rd-review/SKILL.md` 补三档的行为判定标准（不用形容词）
- [x] 明确「同 context 多角度 ≠ 多证人」，升档只在真正分开派发时成立
- [x] `check-artifacts.js` 加条件名枚举校验 + selftest 证伪用例（AC-4）

### O-5 阶段之间只交接文件，不交接结构化回执

**状态**：done　**影响**：rd-build 派 Builder；各阶段之间　**完成于**：2026-08-10

现在的交接是「上一阶段写文件，下一阶段读文件」。
`RD-DONE` 收尾标记 + `_complete: true` 解决了**「有没有写完」**（这个设计 CE 没有，是我们的强项），
但没解决**「写完的东西自述是否可信」**。
Builder 说「跑过了 task.verify」，除了它自己贴的输出，没有对账。

**CE 的做法**：子 skill 干完必须返回**固定字段的结构化回执**，调用方逐条校验。
`ce-work` 返回：改了哪些文件、哪些 unit 完成、验证结果、**有没有改变行为**、

> 回执说「改变了行为」，但验证证据缺失或含糊到看不出行为怎么被保护 →
> 再叫 `ce-work` 一次进「**证据补齐模式**」：不许重新实现，只许回去补证据。
> 第二次还说不清 → 判 blocked，不许往下走。

**怎么改**：给 Builder 定一份返回契约，字段缺失或含糊就打回补证据（不重做）。
候选字段：改动文件清单（跟 `task.files` 白名单对账）、变异体存活数、
`task.verify` 的真实输出、有没有偏离 `task.steps` 及原因。

**完成方式**：

- `check-artifacts.js` 校验已存在的回执（缺字段/空白/占位符点名），缺席只报 advisory、
  对账走 `inflight.agents[].receiptPath`（对存量 `.rd` 完全单调）。
- `rd-build/references/receipt-audit.md` 写证据补齐模式（第一次打回补证据不重做，
  第二次仍不合格判 blocked）。

#### O-8.1 四个「缺口透镜」＋ 把固定问卷改成诊断

现在六类是**每类至少一个具体问题**，不管开场白说得多清楚都要问一轮。
这是固定问卷，不是诊断。用户已经把边界值写清楚了还要按表问一遍——
**这就是流程被弃用的方式**。

CE 的做法是先诊断开场白缺哪一类，缺了才问：

| 透镜 | 诊断什么 | 命中了就问 |
|---|---|---|
| **证据缺口** | 只说了「想要 / 需要」，没指向任何**已经发生过的行为** | 关于这件事，有人已经做过的最具体的一件事是什么——花过时间、付过钱、搭过绕行方案、还是因此弃用过某个工具？ |
| **具体性缺口** | 受益人抽象到 agent 不编造「他是谁」就没法设计 | 说出一个具体的人或一小撮人，以及这东西上线后对那个人**具体变了什么** |
| **反事实缺口** | 没说清今天遇到这问题用户怎么办，也没说不做会怎样 | 现在的绕行方案是什么？哪怕很难看。它让他们付出了什么？ |
| **依恋缺口** | 把某个**解法形状**当成了要做的东西，而不是那个形状本该交付的**价值** | 还能交付真实价值的最小版本长什么样？ |

CE 的关键约束（要一起抄）：

> 这是 **agent 内部分析，不是给用户看的清单**。含糊的开场白可能触发三四个探针，
> 而一个具体、框得很好的开场白**可能一个都不触发**。
> 探针要**折进对话的自然流程**，不是开场先打一梭子。

**待办**

- [x] 四个透镜写进 `rd-spec`，标明是 agent 内部诊断（`references/interview-probes.md`）
- [x] 六类工程问题从「每类必问」改成「先诊断，缺了才问」
- [x] 明确探针与六类的先后：产品维度探针在前（它决定还要不要往下问）

#### O-8.2 拷问退出前没有「组合检查」

一问一答有个固有缺陷：**每个答案都对，合起来有洞**。
现在拷问完直接去写 `spec.md`，中间没有这一步。

CE 的原文：

> 退出对话前，把用户到目前为止说过的话**在脑子里合起来**，
> 找出对话没探过的非显然后果。如果「用户说的 X ＋ 用户说的 Y ＋ 你的默认 Z」
> 会产生一个用户在一问一答里不太可能追踪到的下游效果
> ——「如果静音挂在规则上，而且删除时不警告，那删规则就会静默丢掉暂停状态」
> ——**现在就问，趁还在对话里**。

配一条纪律：后面的确认环节是**残余项的安全网，不是你本可以现在问却偷懒不问的问题的垃圾桶**。

- [x] 一个组合效应问一次，开放式，同探针纪律

#### O-8.3 写文档前没有「我理解得对不对」的确认门

现在是「拷问 → 直接写 spec.md ＋ acceptance.json → 跑 validate-plan」。
用户第一次看到整体是在**成品文档**里，那时候纠正成本已经高了，
而且 `acceptance.json` 已经写完了。

CE 的 Phase 2.5 是**两段式**：内部先打一份三桶草稿
（**用户说的** / **我推断的** / **我排除的**），**不给用户看**；
再从中提炼一份「两个产品同事在写 PRD 前会互相确认的那种话」，最多四节：
在做什么 / 关键取舍 / 不在范围内 / 需要你拍板的残留项。

它踩过的两个坑（原文记录，值得直接采信）：

> 1. 这个拆分之所以存在，是因为**全面审计式的形状给出的细节多到用户根本没法真的表态**，

> 2. 确认门一开始只看「有没有问过阻塞式问题」，结果**用户一次性把 20 多项范围
>    全写在开场白里、因此一个问题都不用问的情况，只拿到了一句话的确认**。
>    后来改成两个信号一起判（问过问题 **或** 档位是 Standard/Deep 都走完整确认）。

「**我推断的**」那一桶最关键——CE 称它是「最值得纠正的表面，

但那是给自己看的，不是拿给用户确认的。

#### O-8.5 用户评估不了的领域，现在是硬问 —— 缺 Blindspot Pass

现在的硬门槛是「不许替用户做产品决策，用户说『你决定』时给建议让他确认」。
这在用户**懂但没决定**时是对的；在用户**根本评估不了**时，
就变成了走过场式的橡皮图章。**这两种情况现在没有区分。**

CE 的原话：

> 这套访谈机制默认用户能评估它问的东西。**在用户不懂的领域这个默认失效了：
> 问题榨出来的是猜测，不是需求。**

触发条件两个：开场就说「我对 X 一窍不通 / 从没碰过认证模块」；
或对话中**连续两次回答表明用户没能力评估问题的实质**
（关键区分：**不是「还没决定」，是「评估不了」**——对一个只是还没拿定主意的专家
触发教学模式，是这条的主要失败模式）。

触发后不是开始教学，而是画一张 **3-7 项的决策地图**，每项 4 行以内：
这是什么（用用户的词）/ 为什么对**这件事**重要 / 2-4 个真实选项各一句权衡 / 推荐哪个。
然后一个多选问题：「哪些想现在细聊？没选的按推荐默认走，记成显式假设。」

三条细节值得一起抄：

- **地图上不许放已经有答案的问题**——代码库或资料能回答的，
  要**带引用展示为既定事实**，不是摆成选项菜单。但**场外解决的问题不算解决**：
  territory 已回答的条目要展示出来，不能默默消化掉。
- **菜单里不许放你自己会否掉的选项**——「用你自己都不会捍卫的选项凑数，
  那不是选择，是稻草人」。被排除的选项写进「为什么重要」里一句话带过。
- **顺便猎杀地雷**：会静默咬人的东西（默认值就是错的数据、会放行坏行的过滤器、
  会损坏输出的转义）、代码强制但没有文档写的潜规则、
  以及**同一件事此前半途而废或被回滚的尝试**——
  「上一次尝试为什么死掉，通常就是地雷所在」。最后这条对存量代码尤其值钱。

**待办**

- [x] 定义两个触发信号，写死「评估不了 ≠ 还没决定」的区分（blindspot-map.md）
- [x] 决策地图格式（3-7 项 / 每项 4 行 / 危险项不给菜单不给默认）
- [x] 未选中项的默认值必须记成 `spec.md` 的显式假设，不许静默采用

#### O-8.6 没区分「真拍板过」和「随口说的」

CE 的**结算测试**：

> 按「它有没有经受过检验」分类，**不是按用户听起来有多确信**。
>
> - **已结算**：对话里摆出过取舍 / 替代方案 / 风险，用户是**看着这些**做的选择
> - **指令**：用户断言了一个没人检验过的选择（冷不丁一句「就用 X 做」）。
>   **不算结算**，有且只有一次被挑战的机会
> - **无标签**：只是 agent 推断或提议、用户从没回应的——普通输入，永远不加标签

配两条硬规则：

- **agent 永远不许给自己未经检验的提议贴标签**，也不许把敷衍的「行吧」升级成「用户明确选择」。
- 一条已结算决策**必须能说出「被否掉的替代方案是什么」**——说不出来的降级成指令。

还有一条**对我们的 L2 / L3 直接有用**：

> 把已结算决策连同被否掉的替代方案一起传给下游，避免重新调研。
> 但**不要传这个决策的论证和理由**（决策作为事实是用来划范围的，论证会锚定他们），
> 而且**任何对抗性 / 验证性的视角必须对「已结算」标记保持盲区**。

最后半句很精妙：审查者如果知道「这是老板拍过板的」，他就不会真的去挑战它了。
这跟我们 `spec-internal.md` 对 L3 保密是同一个形状的问题。

**待办**

- [x] `spec.md` 的「已确认的决策」区分两类（已结算/指令/无标签），并要求已结算写出被否掉的替代方案
- [x] 说不出替代方案的降级成「指令」，享有一次被挑战的机会
- [x] 传给 L2 / L3 时只传决策事实，不传论证；对抗性视角对结算标记保持盲区
      （confirmation-gate.md；结算标记本身不设机械门 —— 用户裁决可证伪化只做 O-2/O-5 两处）
