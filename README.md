# agentflow

# 一句话开发企业级项目

## AI 替你写代码，更替你审代码

**全自动化编程** · 从需求到交付一条龙 · 三道自动审核关卡 · 十三道机械拦截



---

## 你只需要说一句话

```
/wf 我要做一个支持锁定策略的登录功能
```

**然后就没你的事了。**

```
拆需求  →  出方案  →  切任务  →  并行写码  →  三道审核  →  自动修复  →  交付
  AI       3 个 AI     AI       多个 AI      3 个 AI       AI         ✅
```

- **三个 AI 各出一套技术方案**，主控 AI 横向比较后选定
- **按文件边界切成互不冲突的任务**，多个 AI 同时开工
- **三道关卡自动审核**，没过就自动派新 AI 去修，修完从头再走一遍
- **最多三轮**，还不过就停下来告诉你卡在哪

从一句话到能跑的代码，中间不需要你点一次头。

## 别人给你 AI 写代码。我们给你 AI 审代码。

现在遍地都是让 AI 帮你写代码的工具。

**但没人回答那个真正要命的问题——谁来检查这些代码？**

AI 写代码很快。快到你根本来不及看。于是三件事一定会发生：

### 测试全绿，功能是假的

AI 为了让测试通过，会加假数据、加兜底分支、把断言改松。
测试是绿的，代码是坏的。你看到一片绿，以为万事大吉。

### "我做完了"这句话，没人能反驳

因为验收标准当初就没写成能检查的样子。写的是"用户体验要好"——
那 AI 说做完了，你凭什么说没做完？

### 两个 AI 同时改一个文件，后面的把前面的覆盖掉

产生的问题连自动审查都发现不了——审查的人拿到的代码是覆盖之后的，
看起来完全正常。

**agentflow 就是来解决这三件事的。**

## 三道自动审核关卡

```
第一道  不花 AI 额度的检查
        跑类型检查、跑测试。最便宜，放最前面，早失败早省钱
           ↓ 通过
第二道  AI 审代码
        换一个 AI 来审。审之前存快照，审完对一下有没有被中途改过
        它只能看不能改，也不能再派别人
           ↓ 没有必须改的问题
第三道  AI 当用户验收
        找一个完全没看过代码的 AI，让它像真实用户一样把东西用一遍
           ↓ 全部通过
        ✅ 交付
```

**第三道是杀手锏。**

它拿不到代码、拿不到测试、也不知道是怎么实现的，
手里只有"做成什么样算通过"这份清单和一个能跑起来的程序。

**所以它只能真的去用一遍。**

前两道看的是代码，而"能跑但很难用"这类问题，只有真的当一次用户才会撞见。

---

## 它真的抓到过什么

不是理论。每一条都有报告文件为证。

**第一道抓到：配好的检查命令本身是坏的。**
8 个写代码的 AI 全都没碰到——因为它们跑的是具体文件，而配置里写的是整个目录。

**第二道抓到：防篡改功能自己是坏的。**
存快照那个功能记录的指纹，和实际文件对不上。也就是说这个安全机制一直在空转。

**第二道还抓到：一个模块改坏 6 处，测试一处都没报错。**
测试全绿。光看代码，看不出来测试根本没在管事。

**第三道抓到：9 条用起来别扭的地方，其中一条是真的算错了。**
排序算法在暴跌的币上会失效，把真正有价值的标的挤到后面去。

**每一道都抓到了只有它能抓到的东西。**



## 它到底硬拦住了什么

**不靠嘱咐 AI，靠脚本硬拦。** 下面每一条都是代码在管：

| 会出什么问题 | 怎么拦 |
|---|---|
| 测试一个用例都没跑到，命令却返回成功 | 要求命令成功**并且**输出里出现指定字样 |
| 一条标准有好几个要求，只检查了一个 | 有几个要求配几个检查点，全中才算过 |
| 需求阶段就把技术栈定死了 | 需求文字里出现语言、框架名，直接报错 |
| 判断的前提条件没地方写 | 人工判定的标准必须填"什么条件下比对才算数" |
| 同一条命令换个终端结果就反了 | 命令里带嵌套引号直接报错 |
| 审代码的时候代码被人改了 | 审之前存快照，审完对一下 |
| 要审的代码被依赖目录淹没 | 只审任务清单声明过的文件，多改的单独列出 |
| 被打断后不知道做到哪了 | 脚本告诉你当前进度、缺什么、上次断在哪 |
| 中断留下一堆没人认领的截图日志 | 点名列出没被任何报告引用的文件 |
| 该记的进度没记 | 记录和硬盘文件双向对账 |
| 检查过程中偷偷改规则 | 开工时存规则指纹，之后每次比对 |
| "只有我一个人说没问题"被忽略 | 每次都打印结论是谁下的 |
| 主控 AI 跳出流程自作主张 | 七类动作必须先问你，没记录就算违规 |

**十三道机械拦截，一条都不靠自觉。**

## 三分钟装好

```powershell
# 先看看它打算做什么，这一步不会改任何东西
powershell -ExecutionPolicy Bypass -File install.ps1

# 确认没问题再真装
powershell -ExecutionPolicy Bypass -File install.ps1 -Apply -EnableAgentTeams

# 到你的项目目录里初始化
cd D:\your\project
powershell -ExecutionPolicy Bypass -File <agentflow>\scripts\init-workflow.ps1
```

装完重启 Claude Code，输入 `/wf` 开始。

**跑在 Windows 上，不需要 tmux、不需要 WSL、不需要装别的命令行工具。**

初始化脚本是增量的，已有文件不会被覆盖。它会自动识别你的项目是什么语言、
配上对应的检查命令、建好 `.gitignore`，然后把配好的命令实际跑一遍确认能用。

## 七条路线，小任务不走全套

它会先看任务多大，再决定走哪条路：

| 路线 | 用在什么时候 |
|---|---|
| `direct` | 改一两行的小事，直接做 |
| `guarded` | 中等改动，加一道审核 |
| `full` | 完整功能，三道关卡全走 |
| `refactor-safe` | 存量代码重构，默认串行 |
| `diagnose` | 排查问题，先复现再修 |
| `research-only` | 只调研，不写代码 |
| `review-only` | 只审代码 |

**不会拿大炮打蚊子。**

## 核心设计

### 验收清单是整套流程的起点

不要人工审核，前提就是**验收标准在开工前已经能被机器判断**。

- **机器判的**：先写清楚"给什么输入、期望什么输出、用什么标准算相等"，
  等技术方案定了再翻译成具体命令
- **AI 判的**：必须写清楚"从哪个界面去看"、"什么前提下比对才算数"、"要交回什么证据"

说不清楚怎么检查的，不算验收标准，算许愿——会被脚本直接拦下来。

### 光有测试通过不算数

测试通过只说明"代码和测试对得上"，不说明代码是对的。

所以要求做一件事：**故意把代码改坏，看测试会不会报错。**
把大于改成大于等于、把某个判断删掉、把常数加一，改一处跑一次，然后改回去。
测试没报错，说明这处改动测试根本管不着。

实测对比——同一个仓库、同一轮审查：

```
一个模块，改坏 6 处，测试抓到 6 处
另一个模块，改坏 6 处，测试一处都没抓到
```

唯一的差别：前一个模块的任务书里写了"要做这件事"，后一个没写。

### 同一批任务不许改同一个文件

两个 AI 同时改一个文件，后面的把前面的覆盖掉，这种问题自动审查看不出来。

所以任务是按**文件**切的，不是按功能切的。有脚本检查同一批任务的文件清单有没有重叠。

## 什么时候需要你出面

| 时候 | 说明 |
|---|---|
| 第一步问需求 | 需求只能从你这来，省不掉 |
| 主控 AI 想跳出流程做事 | 中途掐掉一个正在干活的 AI、改流程规则、跳过某道检查——必须先问你 |
| 收尾时确认要记哪些经验 | 低成本确认，你不回应它就按自己的判断记 |
| 三轮还没过 | 不正常的情况，正常跑不会触发 |

## 适用边界

**Windows 环境。** 检查命令基于 PowerShell，Mac 和 Linux 上跑不完整。

**纯代码库效果打折。** 没有能跑起来的界面或命令，第三道检查会退化成普通集成测试。

**多个 AI 并行大约费 5 倍额度。** 简单的增删改查用一个 AI 更划算——所以有那七条路线。

**Agent Teams 是 Claude Code 的实验功能**，Windows 上只能用单窗口模式。
用不了会自动降级成一个个来，流程不会中断。

靠的就是这些。

## 改代码要注意

`scripts` 目录下的 `.ps1` 文件必须存成 **UTF-8 with BOM**。

Windows PowerShell 5.1 读没有 BOM 的文件时会按系统默认编码去解，
中文注释直接变乱码，接着引号配不上对，整个脚本报语法错误。

用 VS Code 改的话，右下角编码选 "UTF-8 with BOM"。命令行修：

```powershell
$enc = New-Object System.Text.UTF8Encoding($true)
Get-ChildItem .\scripts -Filter *.ps1 | ForEach-Object {
    $t = [IO.File]::ReadAllText($_.FullName, [Text.Encoding]::UTF8)
    [IO.File]::WriteAllText($_.FullName, $t, $enc)
}
```

**为什么配置用 JSON 不用 YAML**：为了让检查脚本在 Windows PowerShell 5.1 上
不装任何东西就能跑，而 5.1 不支持读 YAML。
检查脚本能不能跑，直接决定这套流程能不能自动化。
