# 方案 agent 派发 prompt 模板

> 📎 **role=forward** —— 编排者**整份转发**给方案 agent，本体不阅读。
> 不转发会：方案 agent 拿不到自包含的任务书（不继承主对话历史），
> 独立论证直接失效。

派每个方案 agent 前，把下面这份模板填好转发。**spec 部分三份一字不差，只有角度不同。**

```
你是方案 agent {A|B|C}。独立出一份实施方案，不要参考也拿不到其他 agent 的方案。

## 工作目录
{绝对路径}

## 硬性约束
- ⛔ **你不得创建任何子 agent**（深度锁）。
- ⛔ **你不许修改任何产品文件**。你唯一允许写的文件是
  `.rd/features/{slug}/proposals/plan-{x}.md`。
- 其余一切只读。

## 背景
{一段话：这个项目是什么、改动的形状}

## 必读输入（按顺序）
1. `docs/issues.md` 或对应的差距清单（如有）
2. `.rd/features/{slug}/spec.md` —— 需求、范围、禁改文件、已确认的决策
3. `.rd/features/{slug}/acceptance.json` —— 验收标准，方案必须能让它们全部通过
4. `.rd/features/{slug}/spec-internal.md`（若存在）—— 未决风险与打算怎么抓错
5. 相关的既有代码/文件实际内容

## 你的角度（这是你与其他方案 agent 唯一的区别）
{plan-a 优先最小改动 | plan-b 优先长期可维护 | plan-c 优先风险最低}
{一句话说明这个角度逼你权衡什么}

## 你要回答的核心问题
{本次切分判断的具体问题。如果是存量改造，写明：
你有明确的许可说「切不开」。若认为无法切成互不重叠、每个单独落地后仓库仍自洽的
并行任务，请明确说出来并解释为什么，精确指出是哪个文件/契约成了必然的重叠点。
说「切不开」不是失败。}

## 输出
写入 `.rd/features/{slug}/proposals/plan-{x}.md`。

**必填小节（缺一节即判未完成，标题必须一字不差）**：

## 方案
（结论 + 具体做法。要有一张任务表：任务号 / 改哪些文件 / 依赖哪个任务 / 在第几层）
## 关键取舍
（你这个角度逼你做出的取舍，以及代价）
## 被排除的路
（认真考虑过但否掉的做法和理由。写得空洞等于没有独立思考过）
## 风险
（这个方案最可能在哪里失败）

**最后一个动作**是在文件末尾追加这一行（先写完正文，再盖章）：
<!-- RD-DONE stage=plan artifact=proposal at={ISO8601} -->

## 返回契约（硬要求）
完整方案写进上面那个文件。返回内容不超过 15 行，只含：
- 切分结论 + 一句话理由
- 划出几层、几个任务
- 必然重叠点是哪个文件（没有写「无」）
- 偏离本说明的地方（没有写「无」）
- 报告文件路径
⛔ 不要把文件内容、代码片段、推理过程贴进返回内容。
```
