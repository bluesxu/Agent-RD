# Blindspot Pass —— 用户评估不了时画决策地图

> 📎 从 `skills/rd-spec/SKILL.md` 抽出。**加载条件**：命中「用户评估不了」任一触发信号时。
> 不读会：对根本评估不了的用户硬问 —— 问题榨出来的是猜测，不是需求。

## 为什么需要它

访谈机制默认用户能评估它问的东西。**在用户不懂的领域这个默认失效了：
问题榨出来的是猜测，不是需求。**

## 两个触发信号

1. 开场就说「我对 X 一窍不通 / 从没碰过认证模块」。
2. 对话中**连续两次回答表明用户没能力评估问题的实质**。

**关键区分：不是「还没决定」，是「评估不了」。**
对一个只是还没拿定主意的专家触发教学模式，是这条的主要失败模式。
专家说「你决定吧」→ 给建议让他确认（走 interview-probes 的提问纪律）；
外行说「你决定吧」→ 触发本文件。两者的判断标准是「有没有能力评估问题的实质」，不是对方的自信。

## 触发后不是开始教学，而是画决策地图

一张 **3-7 项**的决策地图，每项 4 行以内：

1. 这是什么（用**用户的词**，不是你的术语）
2. 为什么对**这件事**重要
3. 2-4 个真实选项，各一句权衡
4. 推荐哪个

然后一个多选问题：**「哪些想现在细聊？没选的按推荐默认走，记成显式假设。」**

## 三条细节

**① 地图上不许放已经有答案的问题。**
代码库或资料能回答的，要**带引用展示为既定事实**，不是摆成选项菜单。
但**场外解决的问题不算解决**：territory 已回答的条目要展示出来，不能默默消化掉。

**② 菜单里不许放你自己会否掉的选项。**
「用你自己都不会捍卫的选项凑数，那不是选择，是稻草人」。
被排除的选项写进「为什么重要」里一句话带过。

**③ 顺便猎杀地雷**（会静默咬人的东西）：
- 默认值就是错的数据、会放行坏行的过滤器、会损坏输出的转义
- 代码强制但没有文档写的潜规则
- **同一件事此前半途而废或被回滚的尝试** —— 「上一次尝试为什么死掉，通常就是地雷所在」。
  最后这条对存量代码尤其值钱。

## 落盘

未选中项的默认值**必须记成 spec.md 的显式假设**，不许静默采用。
被排除了的地雷也要留一行，让后面的方案 agent 知道「这条路踩过坑」。
