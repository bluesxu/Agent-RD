# 策略：ideate —— 方向未定的候选探索

> 适用：任务类型判不出来 / 用户开场是模糊念头（「想做点什么」「哪里还能改进」「给我点想法」）。
> 预算量级：**~5~10 万 token**
>
> **中断处理**：不要预估「能不能一口气跑完」。进度持续落盘：每拿到一个探索 agent 的结果，立刻写进候选草稿，不要攒到阶段末尾一次性写。恢复时以产物为准，不以记忆为准。

## 界定现状 [required]

一次一个问题，问到能界定为止。方向未定不等于没有材料：

- 现在最卡的是什么 / 最近在想什么
- 有没有做过一半、或已经搭了绕行方案的事
- 想改善的块在哪（代码、流程、工具、文档都算）

**用户给不出任何现状线索 → 停下来告诉他「ideate 需要一点抓手」，不要凭空生成。**

## 多方向并行探索 [required]

派 **2~3 个异构 agent 各自找候选方向**：

- **不继承主对话历史**，每个 prompt 自包含（把现状材料全文放进去）
- **异构优先**：同一个模型出三份候选，大概率是同一份候选的三种措辞
- **全部在同一条消息里派出**，然后**立即等待**，停止你自己的一切分析
- 每个 agent 的产出必须包含：**候选方向 + 一句话为什么值得做 + 依据**
- 涉及现有代码的候选必须带 `file:line`；涉及用户判断的带用户原话

## 合并成候选清单 [required]

把各 agent 的候选**去重合并**，产出 **3~5 个排过序的候选**，落盘到 `.rd/ideation/{slug}/candidates.md`（slug 从用户的模糊念头里抽一个词）：

```markdown
## 候选 N：{一句话方向}
- 是什么：{两行内说清}
- 为什么值得做：{依据锚点：file:line 或用户原话}
- 成本量级：{S / M / L / XL，按 rd 分诊口径}
- 风险：{一句话}
```

**被排除的候选单独列一节，不许为空。**

## 让用户挑 [required]

把候选清单呈现给用户：

- 用户选了一个 → **回 rd 的 Phase 1 重新分诊**。这时才有「要做的事」。
- 用户说「都一般」→ 回「界定现状」重新来，或停下。

⛔ **候选不许直接当需求。**选定的方向必须回 rd 重新分诊，不许跳过 Phase 1 / 2 直接进 `rd-spec`。

## 硬门槛

- **不写任何产品代码。**需要验证某个方向可行时，写在临时目录里，验完删掉，并在报告里说明。
- **论证 agent 深度锁 1 层**，不得再派生子 agent。
- **不许派了不等。**
- **「被排除的候选」不许为空。**
- **每个候选必须有依据锚点**（`file:line` 或用户原话）。
