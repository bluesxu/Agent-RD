# 自造对抗性变异 —— 验证测试集够不够用

> 📎 从 `skills/rd-review/SKILL.md` 抽出。**加载条件**：`task.mutationTargets` 非空时。
> 不读会：把变异当成例行公事 —— 变异是**唯一直接检验「测试集够不够用」**的手段，
> 漏掉它，下一轮测试层跑全绿也只是「实现和测试一致」，不是「实现正确」。

Builder 不写测试、不做变异。你是变异测试的唯一作者：
写完 `mutationTargets` 声明的文件的 AC 测试之后，**对它们做一轮自造对抗性变异**，
逐份验证这套测试集能不能把变异体杀掉。

## 怎么造（机械地改，不要靠想象力）

专挑「测试可能没想到」的地方，而不是顺着测试的断言翻面：

- 边界条件只改一格？**试试改两格、试试等号那一侧**
- 守卫条件是复合的？**只摘掉其中一个分支**，而不是整条删掉
- 有没有「删掉这段代码，测试依然全绿」的整块？
- 返回值只差一个字段？**删掉一个字段、换成默认值**
- 算子照下表机械替换，然后**还原**：

| 算子 | 怎么改 |
|---|---|
| 边界 | `<` ↔ `<=`，`>` ↔ `>=` |
| 布尔 | `&&` ↔ `\|\|`，删掉一个 `!` |
| 常数 | `n` → `n±1`，`0` → `1` |
| 守卫 | 删掉一个 `if` 早退 |
| 返回 | 提前 return，或返回默认值 |

每造一个变异体就跑一次测试，然后**还原**。逐条报告：

```
变异测试 src/core/ema.ts
  M1 k 系数 2/(n+1) → 2/n        killed by "AC-1 斜坡夹具末值"
  M2 种子改用第一个收盘价          killed by "AC-1 n=3 完整输出"
  M3 边界弱化一格（< 改 <=）      存活 ← 测试集缺口
  存活 1 / 3
```

## 怎么判

- **存活 0** = 测试集对这个模块够用。
- **存活 > 0** = 测试集有缺口。按缺口的严重程度定级 ——
  能掩盖真实回归的缺口（比如某个错误分支完全没被断言）＝ `coverage-gap`（important），
  并补测试杀掉它，或说明它是等价变异体（改了但行为确实不变）并给出理由。
- **等价变异体不是借口**：说不清「行为确实不变」的存活体，一律按缺口处理。

实跑证据：上一轮 Builder 的 6 个变异体全被杀（看起来修得很好），
但 reviewer 自造的两个变异体**存活了** —— 一个是「边界弱化一格」，
一个是「只摘掉复合守卫的其中一个分支」。Builder 的修复是贴着已知变异体写的，
自造变异体专挑它想不到的地方，是这层检查的真正价值。

**测试通过只说明「实现和测试一致」，不说明「实现是对的」。**
这一步是唯一直接检验「测试集够不够用」的手段。
