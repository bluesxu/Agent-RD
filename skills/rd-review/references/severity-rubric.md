# 三档行为判定标准

> 📎 从 `skills/rd-review/SKILL.md` 抽出。**加载条件**：开始给发现定级时。
> 不读会：分级靠自由心证 —— blocking/important/nit 三档没有写死的判定标准，
> 同一件事在三个 reviewer 手里会得到三个档。

## 为什么是行为条件，不是置信度

模型无法诚实自查「这严重吗」（0.68 和 0.72 没有可观测差别），
但能自查「这条规则没人实现时会静默产出错误结果吗」。
**每一档绑一条模型能诚实自查的行为条件**，而不是形容词。

## 三档的判定条件（权威源：`check-artifacts.js -Sections` 打印的冻结表）

**每个发现必须标注 `- 判定条件: <名字>`**，名字取自下表。缺 / 拼错 → 报告判 partial。

### blocking —— 条件满足任一条即 blocking

| 条件名 | 行为判据（模型能诚实自查的） |
|---|---|
| `contract-break` | 改动对外契约/接口，调用方照新契约写会崩 |
| `wrong-result-silent` | 正常路径产出错误结果而不报错 |
| `fabricated-verification` | 测试/验证存在假绿（断言未锚定、被绕过、mock 过度、被 skip） |
| `guard-evasion` | 守卫被绕过或降级为形式，该拦的没拦住 |

**blocking 未解决不得宣称 review 通过。**

### important —— 条件满足任一条即 important

| 条件名 | 行为判据 |
|---|---|
| `unhandled-failure-path` | 一条真实可触达的失败路径没有处理（异常/超时/空值/边界） |
| `coverage-gap` | 关键路径缺验证，且缺失会掩盖回归 |
| `contract-drift` | 实现与已冻结契约不一致，但当前输入未触发 |
| `performance-risk` | 数据集/负载到真实规模时性能退化到不可接受（能指出现实的规模拐点） |
| `maintainability-trap` | 结构让后续改动成本非线性上升（god object / 紧耦合 / 穿透层） |
| `testability-gap` | 关键行为缺可测接缝，验证只能靠人工/一次性手段 |

### nit —— 条件满足任一条即 nit

| 条件名 | 行为判据 |
|---|---|
| `redundant-logic` | 不改变行为但增加维护负担的重复 |
| `misleading-name` | 命名误导读者 |
| `stale-doc` | 注释/文档与行为不一致，不影响运行 |

**说不出失败场景的发现，降级成 nit 或者不要提。**
存活的变异体不一定是 blocking —— 判断依据是「它存活意味着什么行为不被检测」，
说不出这个，就降成 nit。

## 升档 —— 需要真正独立的多个证人

多个审查者提到同一件事可以升一档，**但前提是那些审查者真正独立派发**。
**同 context 里的多个视角不算多个证人** —— 那是同一个人的三种说法。

这条是**指令**，没有机械检查：`check-artifacts` 验不了「你是不是真独立」，
只能靠派发时的独立性保证。升档时在报告里写明依据。
