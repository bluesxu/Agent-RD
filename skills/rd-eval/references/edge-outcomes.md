# skipped / blocked 标准出口

> 📎 从 `skills/rd-eval/SKILL.md` 抽出。**加载条件**：出现 `skipped` / `blocked` 判定时。
> 不读会：没有出口的时候，人会自己造一个 ——
> 反复尝试够不着的登录墙，或编一个读数、把「我没验到」写成「看起来是对的」。

## `skipped` —— 外部前置条件被墙时的标准出口

有一类失败**不是这个系统的问题**：验收所依赖的**外部**东西够不着了 ——
第三方站点要登录、外部行情接口限流、需要的账号本环境没有。

给它一个专门的终态，理由很直接：**没有出口的时候，人会自己造一个。**
实跑里出现过验收者反复尝试一个够不着的登录墙，直到有人从外面告诉它别试了；
而更坏的分支是编一个读数、或者把「我没验到」写成「看起来是对的」。

判 `skipped` 必须三条同时成立，缺一条就退回 `blocked` 或 `fail`：

1. **阻塞点在被测系统之外** —— 是第三方站点/账号/网络，不是本次交付的代码
2. **有尝试证据** —— 截图或输出，证明你真的试过，而不是看一眼就放弃
3. **写清没验到什么** —— 「AC-10 的哪个可观察点因此没有被覆盖」，一句话点明

```
### AC-10 {name}  ⏭️ skipped
- 外部阻塞: TradingView 需要登录，本环境无可用账号
- 尝试证据: reports/evidence/ac10-login-wall.png
- 因此没验到: 「叠加的 EMA 曲线与本站计算值一致」这一条完全未覆盖
- 本系统侧已验到: 接口返回的 EMA 序列本身（见 AC-10 附带的 api.json）
```

⛔ **`skipped` 不是及格线的后门**：它和 `fail` 一样让整体结论为**不通过**。
唯一的区别是**处置路径** —— `fail` 派 fix agent 改代码，
`skipped` 改不动（代码没问题，是外部够不着），所以直接**升级给编排者**，
由用户裁决：换验证途径、放宽这条 AC、还是接受不覆盖。
那是一次流程外动作，按铁律 7 记进 `run.json` 的 `outOfFlowActions`。

⛔ 内部原因一律不许写成 `skipped`：服务起不来、依赖没装、命令报错
—— 那些是 `blocked`，是本次交付要解决的问题。

## `blocked` 的判定

- **machine 场景**：`check` 命令跑不起来（依赖缺失、环境问题）→ 判定 `blocked`，
  不是 `pass`，也不是 `fail`。说明卡在哪。
- **agent 场景**：判 `pass` 却拿不出证据的，改判 `blocked`。
- **没有证据的通过不算通过。**

`blocked` / `skipped` 都不是 `pass`。整体结论里只要有 `fail` / `blocked` / `skipped`，
结论就是不通过。
